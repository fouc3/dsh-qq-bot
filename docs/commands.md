# 命令与交互

所有命令都发在**私聊**里。识别规则：取消息首 token，**允许一个可选前导 `/`**（QQ 自定义菜单与「指令按钮」填充过来的文本可能带或不带），归一化后匹配命令词。

**通用规则（重要）**：一条命令 if **需要参数却没给参数**，bot 回复该命令的**作用 + 用法**，不做别的。命令名/作用/用法是同一份数据（`dsh-plugin/lib/commands.js`），同时驱动：命令解析、用法回复、QQ 指令面板条目、自定义菜单条目。

## 会话引用（`<目标>`）

`<目标>` 支持两种写法，第二种用于同名/歧义场景：

| 写法 | 例子 | 说明 |
|---|---|---|
| `<会话id>` | `session-3f2a…` | 会话 id 全局唯一 |
| `<目录> <会话id>` | `/home/fouc3/Projects/DSH-QQ-Bot session-3f2a…` | 额外校验该会话确实属于该目录 |
| `当前` | `当前` | 省略时默认就是当前绑定的会话（`停止`/`归档` 可省略 `当前`） |

`<内容>` 是**剩余全部文本**（可以带空格、换行）。解析时先按上表尝试吃掉最长的合法目标前缀，剩下的就是内容；吃不到合法目标则按"参数用法"回复。

## 命令表

### 切换会话

```
切换会话                           → 会话选择卡片（无参即"会话选择"语义，不回复用法）
切换会话 <会话id>                  → 绑定
切换会话 <目录> <会话id>           → 绑定（校验目录）
切换会话 none                      → 解除绑定（此后只能用「发送/延迟发送」指定会话）
切换会话 <目录>                    → 只给了目录：回复用法
```

绑定后，普通消息（非命令文本）直接送进该会话；会话正在跑就先打断再送。

### 新建会话

```
新建会话                           → 选目录卡片（逐层点进目录，最后点「在这里新建」）
新建会话 <目录>                    → 直接在目标目录新建（要求目录已存在）
```

两条路径都会在 `sessionController.create({ cwd })` 之后**默认把当前 QQ 私聊切换到这个新会话**，
并回复「已新建并切换到 …」，随后直接发消息即可开始用。

### 进度

```
进度                               → 当前绑定会话的进度快照（只读，不打断）
进度 <会话id>                      → 指定会话
```

**只读**：只走 `ctx.agents.get` + 会话事件日志（`session.eventAt`），**不 resume、不 cancel、
不发消息**——正在跑的 AI 不受任何影响（这也是它存在的理由：以前想知道进展只能打断它）。

快照内容：状态（运行中/空闲）、第几轮、已跑多久、最近 3 个工具调用（工具名 + 关键参数 + 多久前）、
最近一段 AI 文本。回看事件条数有上限（800 条），不会整份会话读一遍。

> 卡片键盘受平台硬限制：最多 5 行、每行最多 5 个按钮（超了平台会整条
> `40034029 内联键盘行/列超限` 拒收）。所以目录与会话**共用一页预算**、装不下就翻页，
> 导航按钮（返回上级 / 不指定会话 / 在这里新建）永远并进同一行。

`none` 表示"不绑定会话"：普通消息不再投递，只回一句提示，必须用指令指定会话发送。

### 发送

```
发送                               → 进入当前会话的输入态（附件先入列，卡片上的「发送」才投递）
发送 <目标> <内容>                  → 单次投递（不带附件）
```

- **裸发 `发送`**：进入**当前会话的输入态**。之后你发的文字会攒成正文，图片/文件/语音/视频
  自动入列；机器人每次都回一张**预览卡片**（每个附件带自己的「删除」按钮），点卡片上的
  「发送」才把正文 + 附件一起交给 AI。输入态里**不会**把消息直接投给 AI。
  详见 [输入态与附件](#输入态与附件)。
- **带目标与内容**：把一条消息**单次**投递到指定会话，不改绑定、不打断（目标会话忙则排队到下一轮）；
  这种形式**不支持附件**（附件只能走输入态）。
- 参数不足且没绑定会话时 → 回复用法：

  ```
  **发送**
  > 作用：裸发 `发送` = 进入当前会话的输入态…；带参数 `发送 <会话id> <内容>` 仍是单次投递…
  用法：`发送 <会话id> <内容>` 或 `发送 <目录> <会话id> <内容>`
  ```

### 停止

```
停止                               → 停止当前会话当前轮次
停止 <目标>                        → 停止指定会话当前轮次
```
对当前会话没有在跑的轮次时，回一句"该会话当前没有在运行的轮次"。`停止` **不要求**参数，所以无参不会回用法。

### 归档

```
归档                               → 归档当前会话（并解除绑定、从卡片里移除）
归档 <目标>                        → 归档指定会话
```
归档是 dsh 的持久归档（带 `stopActivity`，会请求停止该会话仍在跑的工作）；归档后的会话不能再跑模型步，因此不再出现在会话选择卡片里。

### 延迟发送

```
用法：延迟发送 <目标> <内容>
```
为指定会话登记一条**待发消息**：等该会话"当前这一轮 AI 正常结束"（`turn/end` 且原因为 `completed`）之后再投递。
被用户显式 `停止` 打断的轮、以及被新消息顶替而取消的轮，都**不算正常结束**，不会触发投递。

- **每个会话同时只有一条**待发消息（`目前简易实现仅支持单个会话一条待发消息`）：重复登记覆盖旧值。
- 无参数 / 参数不足 → 回复用法（**不再**"无参查看待发消息"）：

  ```
  **延迟发送**
  > 作用：为指定会话登记一条待发消息，等该会话当前这一轮 AI 正常结束后再投递。
  用法：`延迟发送 <会话id> <内容>` 或 `延迟发送 <目录> <会话id> <内容>`
  ```
- 登记成功回执：`已登记：<标题(会话id)> 本轮结束后投递`

## 会话选择卡片（`切换会话`）

md 正文 + 内嵌键盘；**每次选择都会先尝试撤回上一张卡片**（撤回失败——例如超过 2 分钟——只记 WARN 并跳过，不阻塞）。

```
**切换会话**
当前会话：`<标题(sessionId)>` 或 `none`
目录：`/home/fouc3/Projects`（共 3 个会话）
```

| 控件 | 类型 | data | 行为 |
|---|---|---|---|
| 子目录 / `返回上级` | 回调按钮（`type=1`） | `qqb:dir:<路径>` | 撤回上一张 → 发下一层卡片 |
| 会话 | 指令按钮（`type=2`） | `切换会话 <sessionId>` | **只把文本填进输入框**，由用户自己发送（平台行为：指令按钮不产生互动事件） |
| `不指定会话` | 指令按钮（`type=2`） | `切换会话 none` | 同上 |

会话按钮的 label = 标题（超过 10 字符按宽度截断）+ 运行中标记（`●运行中`）。

## 结束通知与「我需要回复」

每一轮由 QQ 消息拉起的会话，在 `turn/end` 时发一条通知，**区分正常结束与被打断**：

```
正常结束（turn 以 completed 收尾）
<标题>(<sessionId>)已结束

被打断（被新 QQ 消息顶替 / 用户显式停止 / turn 以 aborted 等非 completed 收尾）
<标题>(<sessionId>)被打断
> 打断来自：<打断它的那条消息原文，压成一行、超 60 字截断>
```

打断来源取不到时（例如在 dsh GUI 里取消），就只发「被打断」那一行，不带引用行。
两种通知都带同一个**回调按钮**：label = **`我需要回复`**，`visited_label = 已触发`，`data = qqb:needreply:<sessionId>`。

点击后：

1. 校验点击者白名单、且其绑定会话 == 该 `sessionId`（否则回应 `code=4` 没有权限，不投递）；
2. 该会话正在 running → 回应 **`code=1`**（失败：按钮保持可点、允许重试）并发一条说明（「这一轮还在跑…」）；不投递；
3. 否则向会话注入一条消息并唤醒：`用户点了「我需要回复」。请把上一条消息对应的结果完整地回复给用户。`
4. 回应 `code=0`（客户端提示成功、按钮进终态）；
5. 再发一条 QQ 确认：`已触发，正在请求回复…`。

> 互动回应码是**平台固定语义**，不要随手挑：`0` 成功、`1` 失败（按钮留活口）、
> **`2` 操作太频繁（客户端会直接弹「操作太频繁」）**、`3` 重复操作、`4` 没有权限、`5` 仅管理员。
> 曾经把「会话忙」错报成 `2`，用户点按钮就直接被弹「操作太频繁」。

新的一轮结束时同样会有新的「已结束/被打断 + 我需要回复」，所以可以反复触发。

**被打断的轮发的是「被打断」而不是「已结束」**：新 QQ 消息顶替上一轮、用户显式 `停止`、
或这一轮以 `aborted` 等非 `completed` 收尾，都走被打断那条路径（并尽量带上打断来源）。
只有**被打断的轮收尾**时才不会被通知：还没认领到具体轮次（例如刚发完消息、`turn/start`
都还没到就被取消）时，只记日志、不发通知，避免刷屏。

## 提问卡片（`ask_user_question`）

dsh 提问插件在本桥绑定的会话里提问时，QQ 侧收到一张 md 卡片。**按钮上只写字母**，字母与选项的对照写在**题干与按钮之间的正文里**（善用 MD 排版），选项下面的小字（`description`）也一并列出：

```
**提问 1/2**  ·  `选择部署方式`
要为这次改动选哪种部署方式？

---
**A.** 直接上线
> 影响面小，回滚快
**B.** 先灰度 10%
> 需要额外的开关配置
**C.** 我今天不改
> 维持现状

（第二题同理，用 `---` 分隔）
```

键盘：

| 控件 | data | 说明 |
|---|---|---|
| `A`/`B`/`C`… | `qqq:<callId>:<题序>:<选项序>` | 单选：直接记录；多选：切换选中状态 |
| `其他` | `qqq:<callId>:<题序>:custom` | 之后用户发来的**普通文本**就是该题的"其他"答案 |
| `提交` | `qqq:<callId>:submit` | 结算 |

- 选项多于 5 个时按 A…Z 继续编号；字母 label ≤10 宽度，超宽不换行截断。
- **选中态两处同时标**：正文里该选项前面加 `✅`，按钮自身用平台的
  `render_data.style = 4`（蓝色填充）表示；未选中为 1（蓝色描边）。只靠正文文字不好扫。
- **待答期间命令照常生效**：命令（桥命令与 `/xxx` 内置命令）优先于提问的文本捕获——
  打 `进度`/`停止` 不会被当成这一题的「其他」答案，提问会继续待答。
- **每次选择只撤回并重发「被点的那张」卡片**（显示当前已选状态），其余卡片原地不动；
  撤回失败只记 WARN。
- **不选任何选项直接点「提交」= 跳过**：该题按"空选项、无其他文本"计入答案（与 dsh 的 skipped 语义一致）。
- **一张卡片放不下就拆成多张卡片**：单卡上限 20 个按钮（平台 5 行 × 每行 4 个，含「其他」与「提交」）；
  本次提问的所有卡片一次性发出，**每张都带「提交」**，随便在哪张点提交都算交卷（没答的题按跳过），
  提交时把本次所有卡片一起撤回。
- 只有**单道题自己就放不下**（选项特别多）时才降级交回 dsh GUI，并在 QQ 侧发一条说明——
  降级绝不无声无息（线上踩过：卡片构造返回 `null`，用户什么都看不到，提问一直悬着）。
- 超时（默认 10 分钟）→ 撤回卡片并交回 dsh GUI（`next()`），不吞掉提问。

## 输入态与附件

QQ 私聊里没有真正的输入框，用户没法"先挂一张图、再打字说要求"。所以引入**输入态**：
`发送`（裸发）进入，附件与文字都先攒着，点预览卡片上的「发送」才交给 AI。

**流程**

1. 发 `发送` → 进入**当前会话**的输入态（不打断正在跑的 AI），机器人回一张预览卡片；
2. 你发的**文字**累加成正文（多条拼成一条，边想边打）；**图片/文件/语音/视频**自动入列；
3. 每次输入都会重发预览卡片，每个附件一行、按钮上带自己的 id（`删除 A1`）；
4. 点卡片上的「**发送**」→ 正文 + 语音转写 + 附件一起投给 AI，并清空输入态；
   另有「清空正文」「取消」（清空并退出输入态）。

**没进输入态时直接发来的附件：一律丢弃**，并回一句提示（附件只能走输入态）。

**附件怎么给 AI**

| 类型 | 处理 |
|---|---|
| 图片 | 存进 dsh 附件服务，作为 `image` 块随正文发给模型（模型不支持视觉时由 dsh 自动降级成「图片已存到 <路径>」） |
| 文件 / 视频 | 存进 dsh 附件服务，在**单独一条分节消息**里给出只读副本路径 |
| 语音 | **只用平台给的转写文本**（`asr_refer_text`），本地不做识别；原始音频不下载 |
| 链接卡片（ark） | 当文字处理：`[链接卡片·类型] 标题（描述）链接` |

- 语音转写放在**独立一段**，且排在附件列表**前面**（优先级更高）——转写可能出错，
  混进正文会被模型当成用户原话。
- **语音转写失败要拦住发送**：平台没给转写时该附件标成「无法识别」，点「发送」会被拒绝并提示，
  直到用户把它删掉为止。
- **超过自动下载上限的附件不自动下载**：只登记 url，卡片上写明「未下载」，
  并在给 AI 的分节消息里带上它的 id；模型需要时调用 `qq_fetch_attachment`（参数 `id`，形如 `A3`）
  把它拉下来，工具返回只读副本路径。平台的签名直链会过期，拉不到会如实回报失败。
- 附件 id（`A1`、`A2`…）**永不重用**（跨输入态继续递增），但**只在当次投递里有效**。

**配置**（`cordis.patch.yml` 里的 `config:`）

- `maxAttachmentBytes`：自动下载的单条上限，默认 50 MiB；
- `maxFetchBytes`：模型用 `qq_fetch_attachment` 拉取时的上限，默认 500 MiB。
