# 命令与交互

所有命令都发在**私聊**里。识别规则：取消息首 token，**允许一个可选前导 `/`**（QQ 自定义菜单与「指令按钮」填充过来的文本可能带或不带），归一化后匹配命令词。

**通用规则（重要）**：一条命令 if **需要参数却没给参数**，bot 回复该命令的**作用 + 用法**，不做别的。命令名/作用/用法是同一份数据（`dsh-plugin/lib/commands.js`），同时驱动：命令解析、用法回复、QQ 指令面板条目、自定义菜单条目。

## 会话引用（`<目标>`）

`<目标>` 支持两种写法，第二种用于同名/歧义场景：

| 写法 | 例子 | 说明 |
|---|---|---|
| `<会话id>` | `session-3f2a…` | 会话 id 全局唯一 |
| `<目录> <会话id>` | `/home/fouc3/Projects/DSH-QQ-Bot session-3f2a…` | 额外校验该会话确实属于该目录 |
| `当前` | `当前` | 省略时默认就是当前绑定的会话（`停止`/`归档` 可省略 `当前`） |

`<内容>` 是**剩余全部文本**（可以带空格、换行）。解析时先按上表尝试吃掉最长的合法目标前缀，剩下的就是内容；吃不到合法目标则按"参数用法"回复。

## 命令表

### 切换会话

```
切换会话                           → 会话选择卡片（无参即"会话选择"语义，不回复用法）
切换会话 <会话id>                  → 绑定
切换会话 <目录> <会话id>           → 绑定（校验目录）
切换会话 none                      → 解除绑定（此后只能用「发送/延迟发送」指定会话）
切换会话 <目录>                    → 只给了目录：回复用法
```

绑定后，普通消息（非命令文本）直接送进该会话；会话正在跑就先打断再送。

### 快捷

把常用会话存成快捷入口（命令就叫 **`快捷`**），每条**自带一个 `#编号`**、可以配**自定义备注**（备注里不能有 `#`）。

```
快捷                               → 帮助（分节：切过去 / 管条目 + 当前状态；**不发卡片**）
快捷 加 [备注]                     → 把**当前会话**存成快捷入口（同一个会话只留一条）
快捷 #2                            → 直接切到 #2（不经过会话选择卡片）
快捷 <备注>                        → 同上，用备注认目标
快捷 <会话id>                      → 同上，直接写会话id（`<目录> <会话id>` 也认）
快捷 #2 <消息>                     → **只把消息投给** #2，**不切换**当前绑定
快捷 列出                          → 快捷卡片（点按钮直接切过去；末行是「加当前会话」）
快捷 删 #2                         → 删掉一条（也认备注）
快捷 备注 #2 <新备注>              → 改备注（备注留空 = 清掉，改回显示会话标题）
```

- **子命令中英文都认**（大小写不敏感）：`加`＝`add`/`a`、`删`＝`delete`/`del`/`d`、
  `列出`＝`list`/`l`/`ls`、`备注`＝`rename`/`r`，`帮助`＝`help`/`h`/`?`。
  认不出子命令的词照样先当目标解析，所以备注叫 `add` 之类的会被子命令抢走（别这么起名）。
- **裸发 = 帮助**（用户要求）：只发一段文本 —— **分节排版**（`切过去` / `管条目` 两节 +
  末尾引用块写英文缩写与备注规则），最后附一行当前状态（`现有：#1 …` 或 `还没有快捷会话…`）。
  要卡片就发 `快捷 列出`。以前是一大段"作用"加一行塞满 `|` 的"用法"，读起来一团（用户提过），
  所以这一条命令在命令表里单独带一份分节说明（`COMMANDS[].help`，仍由 `usageText()` 取用）。
- **"直接切换"是它的存在理由**：`切换会话` 要发卡片逐层选、会话按钮还只是把命令**填进输入框**；
  快捷入口一步到位 —— 命令直接切，卡片上的按钮也是**回调按钮（点一下当场切）**。
- **带消息 ≠ 切换**（用户要求）：`快捷 #2 <消息>` 只把消息投给那个会话，**不动当前绑定** ——
  你正在别的会话里干活时，顺手往 #2 丢一条任务不该把自己带走。回执里会写清楚"没有切换"。
  投递语义与 `发送 <会话id> <内容>` 一致：**会打断**目标会话正在跑的轮次、带引用照样生效；
  不想打断就用 `延迟发送 <会话id> <内容>`。
- **编号只增不重用**：删掉 `#2` 不会把 `#3` 补位成 `#2`（编号是记在脑子里的，
  悄悄换目标比留个空号危险得多）。所以编号可能不连续，这是故意的。
- **备注规则**（都是为了"用名字也能切"这件事能成立）：
  - **不能含 `#`** —— `#` 是编号专用前缀，掺进备注就分不清 `#3` 是编号还是名字；
  - **不能是纯数字** —— 否则 `快捷 3` 到底指备注还是 `#3` 说不清；
  - **必须唯一** —— 重名就认不出是哪一条（重名会被拒并告诉你它用在哪个编号上了）；
  - 留空 = 用会话标题显示（标题变了按钮也跟着变）。
- **目标解析顺序**：`#编号`（显式）→ 备注（**最长前缀**匹配，所以备注可以带空格：
  `快捷 我的 前端 帮我看下` = 把「帮我看下」投给备注「我的 前端」）→ **会话id / `<目录> <会话id>`**
  （走 `切换会话` 同一套 `sessions.resolveRef` 规则）→ 纯数字（当编号）。
- **认不出的编号会明确报错**（不是静默回帮助）：`没找到快捷 #9。现有：#1 …`，
  因为"我明明存过 #9"必须让你马上知道；目标会话**已删除/已归档**时也会说清楚并提醒 `快捷 删 #9` 清掉。
- **卡片**（`快捷 列出`）：正文写明当前会话、共几条、以及备注/编号规则与"带消息不切换"；
  按钮一条一个（label 就是 `#编号 备注`，当前那条标蓝），**末行**是「加当前会话」。
  点任意按钮后都会**重发一遍卡片**（标出新的"当前"）；卡片最多列 8 条
  （平台键盘最多 5 行、每行 2 个，还要留一行给「加当前会话」），超出的用 `快捷 #编号` 直达。
- 卡片会**撤回上一张**（和其他卡片一样），撤回失败只记日志。

### 新建会话

```
新建会话                           → 选目录卡片（逐层点进目录，最后点「在这里新建」）
新建会话 <目录>                    → 直接在目标目录新建（要求目录已存在）
```

两条路径都会在 `sessionController.create({ cwd })` 之后**默认把当前 QQ 私聊切换到这个新会话**，
并回复「已新建并切换到 …」，随后直接发消息即可开始用。

**选目录卡片**的导航行（只有这条命令的卡片有这些按钮；`切换会话` 的卡片模板不同，没有）：

```
返回上级 | 新建目录 | 在这里新建
删除目录（只有空目录才有，**单独占一行**）
```

- **新建目录**：点它之后会换成一张提示卡片（自带一个明确的「**取消**」按钮），
  你**发一条消息写目录名**（只能一层，不能带 `/`、`\`、`..`），机器人就在**当前浏览目录**下
  建出来，并**默认 cd 进去**（把卡片换成新目录那张，接着点「在这里新建」就建在这里）。
  名字不合法/已存在会保持"等名字"状态让你重发；点「取消」或发任意命令都能退出。
- **删除目录**：**只在"彻底空的目录"**（没有任何文件、子目录、隐藏文件）里出现，
  **单独占一行**（破坏性动作不和导航挤在一起）。它是**两步确认**：第一步只把卡片换成确认页
  （只有「取消 / 确认删除」两个按钮），第二步才真删；只删空目录（`rmdir`），
  非空会被 `ENOTEMPTY` 挡住并如实回报——所以就算手工拼一个 `rmdir2:` 回调也删不掉有内容的目录。
- **Web 端可见（自动化，不给模型工具）**：**在目录里新建会话的那一刻**就把该目录
  注册成 dsh 工作区（`workspaceRegistry.create(path)` → `workspace.attachSession(sessionId)`，
  与 dsh 自己的创建流程一致）——否则 dsh Web 侧栏按工作区分组，QQ 建出来的文件夹和会话
  **整个都看不到**（线上踩过）。点「新建目录」建出来的目录也**当场**注册，侧栏马上看得到。
- **补登记（自愈）**：网关每次同步（含插件/网关重启后）会补登记"本桥碰过的"目录与会话：
  当前绑定会话、本桥建出来的会话/目录（状态里的 `createdSessions` / `createdDirs`）、
  **跑过轮次的会话**（`notices` 里 `sessionId:turn` 的 key）、输入态与延迟发送里提到的会话。
  后两条正是一条"历史遗留"能被捞回来的依据；**不会**去注册用户其它几百个会话的 cwd
  （那会把侧栏塞满）。
- 这两条都是**自动的**，没有为此注册任何模型工具（AI 用不上它）。

### 状态

```
状态                               → 当前绑定会话的状态快照（只读，不打断）
状态 <会话id>                      → 指定会话
进度 ...                           → 同上（`进度` 是旧名，仍认，见 commands.js 的 ALIASES）
```

**只读**：只走 `ctx.agents.get` + 会话事件日志（`session.eventAt`）**加上两条 durable 会话投影**
（`model/selection`、`permissions`），**不 resume、不 cancel、不发消息**——正在跑的 AI 不受任何影响。
因为读的是投影，**冷会话（没有活 agent）也照样给得出模型与权限**（读不到就写「（读不到）」）。

抬头四行（用户要求）：

- `> 会话：<标题(会话id)>`；
- `> 模型：<provider> / <model>`；
- `> 权限：<当前权限的中文显示名>`（同 `权限` 卡片那套名字，如「工作区内修改」）；
- `> 状态：运行中（第 N 轮，已跑 X）` / `空闲（没在跑，下面是最近一轮的情况）` /
  `没有活跃的 agent（这一轮没在跑）`。

> 用户要求（2026-10-16）：标题从「进度快照」改成「**状态**」（命令也从 `进度` 改成 `状态`），
> 抬头补上**模型**与**权限**，并**去掉**原来那句「说明：只读查询，没有打断它」。
> 旧名 `进度` 保留为**别名**：桥里认不出的文本会被当普通消息投给 AI，留别名免得手滑把「进度」
> 发给模型（指令面板与菜单里只列新名）。

快照内容：跑没在跑、第几轮、已跑多久、最近 3 个工具调用（工具名 + 关键参数 + 多久前）、
以及**分开的两段输出**（用户要求）：

- **最近一段思考**＝最近的 `reasoning` 块；
- **最近一段正文**＝最近的 `text` 块；

两段**都用同一套措辞**标出步号与距离：「（第 14 步，距最新第 34 步隔 20 步）」，
就是最新一步时写「（第 14 步，就是最新一步）」。为什么两段都标：线上用户看到
「思考（第 95 步）」配「正文（第 95 步，距最新第 100 步隔 5 步）」，以为两段自相矛盾 ——
其实两段都是第 95 步的输出，只是当时只有正文带了距离（那 5 步是在跑的步骤/纯工具步骤，
还没有新输出）。以前只有一段「最近一段输出」，实际常常是 reasoning（看着像正文，其实不是），
所以拆开。

步号取自事件里的 `step`（`step/start` 与 `assistant/message`/`tool/call` 都带）；拿不到步号时
只省略标注，不印 NaN、不报错。回看事件条数有上限（2000 条），不会整份会话读一遍。

> 卡片键盘受平台硬限制：最多 5 行、每行最多 5 个按钮（超了平台会整条
> `40034029 内联键盘行/列超限` 拒收）。所以目录与会话**共用一页预算**、装不下就翻页，
> `新建会话` 卡片的导航按钮（返回上级 / 新建目录 / 在这里新建 / 删除目录）永远并进同一行。

`none` 表示"不绑定会话"：普通消息不再投递，只回一句提示，必须用指令指定会话发送。

### 发送

```
发送                               → 进入当前会话的输入态（附件先入列，卡片上的「发送」才投递）
发送 <目标>                        → 进入**那个会话**的输入态
发送 <目标> <内容>                  → 单次投递（不带附件）
```

- **裸发 `发送`**：进入**当前会话的输入态**；**只给目标**（`发送 <会话id>` / `发送 <目录> <会话id>`）
  则进入**那个会话的输入态**（目标不存在才回用法/报错）。之后你发的文字会攒成正文，
  图片/文件/语音/视频自动入列；机器人每次都回一张**预览卡片**（每个附件带自己的「删除」按钮），
  点卡片上的「发送」才把正文 + 附件一起交给 AI。输入态里**不会**把消息直接投给 AI。
  详见 [输入态与附件](#输入态与附件)。
- **带目标与内容**：把一条消息**单次**投递到指定会话——和输入态的「发送」同义，**会打断**
  目标会话正在跑的轮次（不想打断就用 `延迟发送`）；这种形式**不支持附件**（附件只能走输入态）。
  **带引用时引用生效**：被引用的那条会以 `[引用的消息] <原文>` 拼在正文前面（与普通消息同格式），
  AI 才知道用户在指哪一条（以前命令路径把 `event.quote` 丢了，引用等于没用）。
  被这样点名说话的会话**也能正常回 QQ**（不要求它是"当前绑定会话"：桥会记住"最近一次从 QQ
  跟这个会话说过话的人"；线上踩过显式指定的会话回话被拒、报"该会话当前没有绑定 QQ 私聊"）。
- **有内容的输入框不会被静默换目标**：里面已经有正文/附件时，`发送 <别的会话>` 会被拒绝并提示
  「先发送或取消」——直接切会把攒好的东西丢掉。
- 参数不足且没绑定会话时 → 回复用法：

  ```
  **发送**
  > 作用：发 `发送` = 进入当前会话的输入态，发 `发送 <会话id>` = 进入那个会话的输入态…
  用法：`发送` 或 `发送 <会话id>` 或 `发送 <会话id> <内容>`
  ```

### 停止

```
停止                               → 停止当前会话当前轮次
停止 <目标>                        → 停止指定会话当前轮次
```
对当前会话没有在跑的轮次时，回一句"该会话当前没有在运行的轮次"。`停止` **不要求**参数，所以无参不会回用法。

### 归档

```
归档                               → 归档当前会话（并解除绑定、从卡片里移除）
归档 <目标>                        → 归档指定会话
```
归档是 dsh 的持久归档（带 `stopActivity`，会请求停止该会话仍在跑的工作）；归档后的会话不能再跑模型步，因此不再出现在会话选择卡片里。

### 延迟发送

```
延迟发送                           → 进当前会话的输入态（延迟投递）
延迟发送 <目标>                    → 进**那个会话**的输入态（延迟投递）
延迟发送 <目标> <内容>              → 直接登记（不带附件）
```

**和 `发送` 共用同一套输入态面板**，区别只有投递时机：

- `发送` = **打断**当前轮次，立刻投给 AI；
- `延迟发送` = **不打断**：登记为待发消息，等该会话"当前这一轮 AI 正常结束"
  （`turn/end` 且原因为 `completed`）之后再投递。被用户显式 `停止` 打断的轮、
  以及被新消息顶替而取消的轮，都**不算正常结束**，不会触发投递。

投递时**先等驱动真的空闲**（`agent.whenIdle()` 结算 / `status !== 'running'`），再用
**和普通发送同一条**投递路径（`deliver` → `followup`）交出去。为什么必须等：`turn/end`
处理器里驱动的 `phase.kind` 还是 `running`，此时 `followup` 的唤醒会被 dsh 的 `wakeDriver`
丢掉（它只在 idle / maintenance / "已 abort" 时才唤醒或登记唤醒），消息会一直挂在 dsh 界面的
**「待发送」**里没人捡（2026-10-16 线上事故；详见 README「延迟投递：必须等驱动真的空闲」）。
等不到（有别的轮次在跑）也照样投：那条消息由那一轮收尾时捡走，不会丢。

延迟投出去的这一轮**也算 QQ 的一轮**（`fromQqUser()` 把 `delayed` 与 `qq` 一视同仁）：
照常注入每轮 QQ 上下文（模型知道要用 `qq_reply` 回话），结束后照发「已结束」+「我需要回复」。

卡片上的主按钮在延迟模式下叫「**延迟发送**」，正文也写明"不打断、本轮结束后投递"；
点它之后回一份 `**已登记**（延迟投递）` 预览（正文/语音转写/附件清单都在）。

- **每个会话同时只有一条**待发消息：`延迟发送 <目标> <内容>` 重复登记覆盖旧值；
  输入态登记同样写入这一格（也会覆盖）。
- 登记成功回执：`已登记：<标题(会话id)> 本轮结束后投递`
- 延迟投递不限于纯文本：输入态登记的**图片与附件/语音分节**会一起带过去。
- **带引用同样生效**：`延迟发送 <目标> <内容>` 带引用时，登记的内容也是
  `[引用的消息] <原文>` + 正文（与 `发送` 一致）。

### 权限

```
权限                               → 权限卡片（点一下即切换当前会话的级别）
权限 <级别>                        → 直接设定
```

管的就是 dsh Web 里那个「仅可查看 / 工作区内修改 / 完全权限 / Auto review」选择器
（服务 `ctx.permissionPresets`：`catalog()` 取可选项、`current(session)` 取当前、`set(session, value)` 切换，用可选访问 `ctx.get`，没有该服务的 profile 照常激活）。
**作用对象是当前绑定会话**（dsh 的权限预设是 per-session 的）；没绑定会话时回一句"先 `切换会话`"。

- 不带参数：发卡片。正文列出每个级别（序号 + 名字 + 一句说明）并标出**当前**项；
  按钮是回调按钮，**每行尽可能放两个**（用户要求）；若 2 个/行会让整卡超出行数上限，
  自动加宽到 3、4、5 个/行（`buttonsPerRowFor`），保证整卡合法；当前项 `style=1`（蓝）、
  其余 `style=0`（灰）。
- **显示名跟 Web 同款中文**：`catalog()` 给的 `name` 来自部署配置（线上没配就是英文
  `Read Only` 之类），而 Web 选择器用的是它自己的 i18n 文案 —— 所以这里按预设 key 覆盖：
  `read-only`→仅可查看、`workspace-write`→工作区内修改、`danger-full-access`→完全权限、
  `auto`→Auto review、`custom`→自定义；其它档回退服务给的名字（kebab key 则 Title Case，
  与 Web 的 `displayPresetName` 一致）。
- 带参数：直接设定。级别认**中文名**（`完全权限`）、**英文 key**（`read-only`）、
  **别名**（`只读`/`workspace`/`danger`/`auto`）或**卡片上的序号**（`2`）；认不出就回错误 + 用法。
- 点按钮：切换 → 回执「已把 **<标题>** 的权限切成 **完全权限**（不限制）」→ 重发卡片（新的"当前"）。
- 没有权限服务时如实回「这个部署没有权限服务」，不报错。

### 模型

```
模型                                        → 模型卡片（提供商 → 模型 → 确认 三级）
模型 <提供商>/<模型名字>                     → 直接切（默认当前会话，不过确认卡片）
模型 <提供商>/<模型名字> <会话id>            → 切给指定会话
```

管的就是 dsh Web 里那个模型选择器（服务 `ctx.sessionController`：
`modelCatalog()` 取当前可路由的提供商/模型、`selectModel({sessionId, provider, model})` 切换
—— 注释里写明它会**显式 resume 该会话**，所以冷会话也能切、不用先启动 agent；
`projections({sessionId})` 只读地取 `model/selection` 投影，用来标"当前"。
同样是可选访问 `ctx.get`，没有该服务的 profile 照常激活）。

**作用对象默认是当前绑定会话**，末尾的可选**会话id**可以切给别的会话（那条路径不要求先绑定它）。

- 不带参数：发卡片。**第一级是提供商**：每行最多 **2 个**（用户要求，避免挤成窄条），
  超过 10 个提供商才出现翻页行（每页 8 个）；正文里标出当前模型与提供商/模型总数，
  读不到模型的提供商会单独列一行。
- 点提供商进入**第二级**：这个提供商的模型列表，每行最多 **1 个**，超过 4 个才翻页（每页 3 个）；
  正文里给出序号 + 完整名字 + id + 一句说明，当前那一档标 ✅；导航行只有「返回」。
- **点一个模型先出「确认」卡片**（第三级，用户要求），三个都是**交互式回调按钮**：
  - **应用到当前会话**（蓝）＝立刻切；切完把模型列表卡片重发一遍（正文「✅ 已切到 …」、新档标成当前）；
  - **切到其他会话**（灰）＝**交互式**：换成一张提示卡片，用户下一条消息写出**会话id**，
    就切给那个会话（认不出会保持等待并说清楚；不想切了点卡片上的「取消」回确认卡片）。
    这条分支**不再**用"把命令填进输入框"那种方式（用户明确要求改成交互式）；
  - **返回**（灰）＝回到该提供商的模型列表继续挑。
- 带参数：直接切（**不**过确认卡片）。
- **按钮 label 不再自己砍名字**（用户要求：交给 QQ 尽量多显示）：平台文档只写「按钮上的文字」，
  SDK 里"at most 10 characters"是旧文档的说法，以前按「10 个显示宽度（中文算 2）」截断等于把中文
  砍到 5 个字。现在模型卡片：提供商按钮（每行 2 个）上限 24 个显示宽度、**模型按钮（每行 1 个）
  上限 60**（几乎照发全名，只有病态长名字才有省略号）；同一键盘内的按钮 id 按序编号，避免
  截断后的 label 撞车。
- 带参数：直接切。提供商与模型都**认 id 或显示名**（大小写、空格、`-`/`.` 都宽松匹配），
  也认**卡片上的序号**（`2/3` = 第 2 个提供商的第 3 个模型）；不带斜杠时只有"全库唯一命中"才认，
  否则报歧义并给出完整写法。切失败（会话锁了模型、认不出）都如实回报 + 回用法。
- 没有模型服务（或提供商全都读失败）时如实回一句，不报错。

## 会话选择卡片（`切换会话`）

md 正文 + 内嵌键盘；**每次选择都会先尝试撤回上一张卡片**（撤回失败——例如超过 2 分钟——只记 WARN 并跳过，不阻塞）。

```
**切换会话**
当前会话：`<标题(sessionId)>` 或 `none`
目录：`/home/fouc3/Projects`（共 3 个会话）
```

| 控件 | 类型 | data | 行为 |
|---|---|---|---|
| 子目录 / `返回上级` | 回调按钮（`type=1`） | `qqb:dir:<路径>` | 撤回上一张 → 发下一层卡片 |
| 会话 | 指令按钮（`type=2`） | `切换会话 <sessionId>` | **只把文本填进输入框**，由用户自己发送（平台行为：指令按钮不产生互动事件） |
| `不指定会话` | 指令按钮（`type=2`） | `切换会话 none` | 同上 |

会话按钮的 label = 标题（超过 10 字符按宽度截断）+ 运行中标记（`●运行中`）。

## 斜杠命令（`/xxx`）

QQ 里发 `/compact`、`/goal resume` 这类 **dsh 内置命令**，本桥直接交给 `ctx.commands.execute`
执行（**不经模型**），命令的输出回给 QQ。

- **不存在的命令：明确回绝，绝不投给 AI**（用户要求）。认不出时回一条
  `没有 /xxx 这个命令，**这一条没有发给 AI**。`，并列出**这台会话真正可用的命令**
  （`ctx.commands.list(agent)`），再告诉你怎么把"以 `/` 开头的话"当消息发出去。
  以前这种命令会**回落到普通消息**被投进会话，模型只好对着一条不存在的命令瞎答。
- **没绑定会话 / 没有活 agent** 时发 `/xxx` 同样回绝（不当普通消息），并提示先 `切换会话`。
- **例外只有 `/feedback`**：它是真命令、桥不兼容（既不收纳进菜单也不执行），仍按**普通消息**处理。
- **想发以 `/` 开头的话**（例如一个绝对路径）：把开头那个换成**全角 `／`**
  （`／tmp/x 看一下`），它就不会被当成命令截走，而是正常投给 AI。
- `/plan <文本>` 是唯一的"命令 + 消息"拆分，见下一节。

## dsh 内置命令：`/plan <文本>`

dsh 的 `/plan` 输入是 `[off|message]`：文本非 `off` 时会**进入 plan 模式并把这段文本
`agent.steer()` 塞进会话**（`source` 是普通 user）。那条 steer 起出来的轮次**不经过本桥**：
没有轮次跟踪 → QQ 侧没有思考/进度流、没有「已结束 + 我需要回复」通知，
也没有"这条消息来自 QQ、要用 `qq_reply` 回"的上下文 → 线上表现为**发了没反应**。

所以本桥自己拆这一行：

- `/plan <文本>` → 只把 `/plan` 交给 dsh（切模式，不 steer），`<文本>` 走**本桥正常投递**
  （注入 QQ 上下文、起/打断轮次、有进度与结束通知）；
- `/plan`、`/plan off`、`/plan on` 与其它命令（`/resume <id>` 一类）**原样执行**，不拆；
- plan 模式下模型提交计划（`exit_plan_mode`）时，本桥会把**计划正文转发到 QQ**
  （host 的审批界面 QQ 端看不到），并在该轮的注入上下文里提醒模型"计划也要用 `qq_reply` 发一份"。
  **审批仍在 dsh 的审批界面完成**，QQ 端只做"看得到"。

## 结束通知与「我需要回复」

每一轮由 QQ 消息拉起的会话，在 `turn/end` 时发一条通知，**区分正常结束与被打断**：

```
正常结束（turn 以 completed 收尾）
<标题>(<sessionId>)已结束

被打断（被新 QQ 消息顶替 / 用户显式停止 / turn 以 aborted 等非 completed 收尾）
<标题>(<sessionId>)被打断
> 打断来自：<打断它的那条消息原文，压成一行、超 60 字截断>
```

打断来源取不到时（例如在 dsh GUI 里取消），就只发「被打断」那一行，不带引用行。
两种通知都带两个按钮（同一行）：

| 按钮 | 类型 | 行为 |
| --- | --- | --- |
| **`我需要回复`** | 回调（`type=1`，`data = qqb:needreply:<sessionId>`） | 让 AI 把上一条消息的结果重发一遍（见下） |
| **`发送消息`** | 指令（`type=2`） | 只把 `发送 <sessionId>` **填进 QQ 输入框**（用户自己按发送）→ 进该会话的输入态，可以写正文/加附件，最后点输入态卡片上的「发送」投递 |

点击后：

1. 校验点击者白名单、且其绑定会话 == 该 `sessionId`（否则回应 `code=4` 没有权限，不投递）；
2. 该会话正在 running → 回应 **`code=1`**（失败：按钮保持可点、允许重试）并发一条说明（「这一轮还在跑…」）；不投递；
3. 否则向会话注入一条消息并唤醒：`用户点了「我需要回复」。请把上一条消息对应的结果完整地回复给用户。`
4. 回应 `code=0`（客户端提示成功、按钮进终态）；
5. 再发一条 QQ 确认：`已触发，正在请求回复…`。

> 互动回应码是**平台固定语义**，不要随手挑：`0` 成功、`1` 失败（按钮留活口）、
> **`2` 操作太频繁（客户端会直接弹「操作太频繁」）**、`3` 重复操作、`4` 没有权限、`5` 仅管理员。
> 曾经把「会话忙」错报成 `2`，用户点按钮就直接被弹「操作太频繁」。

新的一轮结束时同样会有新的「已结束/被打断 + 我需要回复」，所以可以反复触发。

**被打断的轮发的是「被打断」而不是「已结束」**：新 QQ 消息顶替上一轮、用户显式 `停止`、
或这一轮以 `aborted` 等非 `completed` 收尾，都走被打断那条路径（并尽量带上打断来源）。
只有**被打断的轮收尾**时才不会被通知：还没认领到具体轮次（例如刚发完消息、`turn/start`
都还没到就被取消）时，只记日志、不发通知，避免刷屏。

## 提问卡片（`ask_user_question`）

dsh 提问插件在本桥绑定的会话里提问时，QQ 侧收到一张 md 卡片。**按钮上只写字母**，字母与选项的对照写在**题干与按钮之间的正文里**（善用 MD 排版），选项下面的小字（`description`）也一并列出：

```
**提问 1/2**  ·  `选择部署方式`
要为这次改动选哪种部署方式？

---
**A.** 直接上线
> 影响面小，回滚快
**B.** 先灰度 10%
> 需要额外的开关配置
**C.** 我今天不改
> 维持现状

（第二题同理，用 `---` 分隔）
```

键盘：

| 控件 | data | 说明 |
|---|---|---|
| `A`/`B`/`C`… | `qqq:<callId>:<题序>:<选项序>` | 单选：直接记录；多选：切换选中状态 |
| `其他` | `qqq:<callId>:<题序>:custom` | 之后用户发来的**普通文本**就是该题的"其他"答案 |
| `提交` | `qqq:<callId>:submit` | 结算 |

- 选项多于 5 个时按 A…Z 继续编号；字母 label ≤10 宽度，超宽不换行截断。
- **选中态两处同时标**：正文里该选项前面加 `✅`，按钮自身用 `render_data.style = 1`（蓝）表示，
  未选中为 `0`（灰）。只靠正文文字不好扫。
  （注意：**不要用 style 4**——线上客户端把它渲染成白色，正好会把"选中/主操作"看成次要按钮。）
- **待答期间命令照常生效**：命令（桥命令与 `/xxx` 内置命令）优先于提问的文本捕获——
  打 `状态`/`停止` 不会被当成这一题的「其他」答案，提问会继续待答。
- **每次选择只撤回并重发「被点的那张」卡片**（显示当前已选状态），其余卡片原地不动；
  撤回失败只记 WARN。
- **不选任何选项直接点「提交」= 跳过**：该题按"空选项、无其他文本"计入答案（与 dsh 的 skipped 语义一致）。
- **一张卡片放不下就拆成多张卡片**：单卡上限 20 个按钮（平台 5 行 × 每行 4 个，含「其他」与「提交」）；
  本次提问的所有卡片一次性发出，**每张都带「提交」**，随便在哪张点提交都算交卷（没答的题按跳过），
  提交时把本次所有卡片一起撤回。
- 只有**单道题自己就放不下**（选项特别多）时才降级交回 dsh GUI，并在 QQ 侧发一条说明——
  降级绝不无声无息（线上踩过：卡片构造返回 `null`，用户什么都看不到，提问一直悬着）。
- **提交后留一条结果预览**：卡片会被撤回（否则聊天里一堆积压卡片），但撤回之后立刻发一条
  纯文本「**提问结果** · N 题」，逐题列出选了什么（`✅ 选项` / `✍️ 其他：…` / 「没选，按跳过处理」），
  用户回头还能核对。
- 超时（默认 10 分钟）→ 撤回卡片并交回 dsh GUI（`next()`），不吞掉提问。

## 输入态与附件

QQ 私聊里没有真正的输入框，用户没法"先挂一张图、再打字说要求"。所以引入**输入态**：
`发送`（立即投递）或 `延迟发送`（本轮正常结束后投递）进入，附件与文字都先攒着，
点预览卡片上的「发送」/「延迟发送」才交出去。两个命令**共用这一套面板**，只是 `mode` 不同。

**流程**

1. 发 `发送`（当前会话）或 `发送 <会话id>`（指定会话）→ 进入**该会话**的输入态
   （不打断正在跑的 AI），机器人回一张预览卡片；`延迟发送` / `延迟发送 <会话id>`
   进入同样的输入态，但模式是**延迟投递**（卡片标题带「（延迟投递）」、主按钮叫「延迟发送」）；
2. 你发的**文字**累加成正文（多条拼成一条，边想边打）；**图片/文件/语音/视频**自动入列；
3. 每次输入都会重发预览卡片，每个附件一行、按钮上带自己的 id（`删除 A1`）；
4. 点卡片上的「**发送**」→ 正文 + 语音转写 + 附件一起投给 AI（**打断**当前轮次），并清空输入态；
   延迟模式下点「**延迟发送**」→ 只**登记**，等这一轮正常结束后再投（不打断）；
   另有「清空正文」「取消」（清空并退出输入态）；
   **按钮配色**：主操作（发送/延迟发送）＝蓝 `style=1`，取消/清空正文/删除附件＝灰 `style=0`
   —— 反过来（取消蓝、发送白）会让用户点错，线上已经踩过一次；破坏性动作（确认删除目录）用红 `style=3`。
5. 卡片撤回后立刻发一条**最终预览**（`**已发送**` / `**已登记**（延迟投递）`：正文 N 字、
   语音转写、附件清单），用户回头能核对"到底发出去了什么"。

**没进输入态时直接发来的附件：一律丢弃**，并回一句提示（附件只能走输入态）。

**附件怎么给 AI**

| 类型 | 处理 |
|---|---|
| 图片 | 存进 dsh 附件服务，作为 `image` 块随正文发给模型（模型不支持视觉时由 dsh 自动降级成「图片已存到 <路径>」） |
| 文件 / 视频 | 存进 dsh 附件服务，在同一条消息里**单独一个块**（`## 用户随消息附带的附件`）给出只读副本路径 |
| 语音 | **只用平台给的转写文本**（`asr_refer_text`），本地不做识别；原始音频不下载 |
| 链接卡片（ark） | 当文字处理：`[链接卡片·类型] 标题（描述）链接` |

- **整次投递只有一条消息**：语音转写、附件清单、正文各是一个 content 块（分别带 `##` 标题），
  图片是随消息的 `image` 块。为什么不让它们各占一条消息：`agent.followup()` 的语义是
  **"这条消息独占自己的一轮"**，连发两条会让第二条挂成"待发送"等下一轮——线上踩过：
  附件清单先跑了，正文卡在待发送里。
- 语音转写是**独立一块、排在附件块前面**（优先级更高）——转写可能出错，
  混进正文会被模型当成用户原话。
- **语音转写失败要拦住发送**：平台没给转写时该附件标成「无法识别」，点「发送」会被拒绝并提示，
  直到用户把它删掉为止。
- **超过自动下载上限的附件不自动下载**：只登记 url，卡片上写明「未下载」，
  并在给 AI 的附件块里带上它的 id；模型需要时调用 `qq_fetch_attachment`（参数 `id`，形如 `A3`）
  把它拉下来，工具返回只读副本路径。平台的签名直链会过期，拉不到会如实回报失败。
- 附件 id（`A1`、`A2`…）**永不重用**（跨输入态继续递增），但**只在当次投递里有效**。
- 卡片操作行的按钮顺序：**取消在左、发送在右**（`取消 | 清空正文 | 发送`）。

**配置**（`cordis.patch.yml` 里的 `config:`）

- `maxAttachmentBytes`：自动下载的单条上限，默认 50 MiB；
- `maxFetchBytes`：模型用 `qq_fetch_attachment` 拉取时的上限，默认 500 MiB。
